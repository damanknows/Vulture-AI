## 1. Standards and official sources

### R1. CVSS v4.0 Specification
- **Title:** Common Vulnerability Scoring System version 4.0: Specification Document
- **Authors / body:** FIRST.Org, Inc. (CVSS-SIG)
- **Date:** released 2023-11-01 (per FIRST page); document version 1.2
- **Venue:** FIRST official specification
- **Link:** https://www.first.org/cvss/v4.0/specification-document
- **Contribution:** Defines Base (CVSS-B), Threat (CVSS-BT), Environmental (CVSS-BE), and Supplemental metric groups. Threat metric E replaces the v3.1 Exploit Code Maturity. Environmental metrics include CR/IR/AR and Modified Base metrics. Supplemental metrics do not change the score (Automatable, Recovery, Provider Urgency, etc.).
- **Limitations (per the document):** the Base score "assumes the reasonable worst-case impact", and Threat and Environmental values are "the responsibility of the CVSS consumer".
- **Relationship to Vulture-AI:** VRS's `C` term is CVSS base severity (v3-style base score in the benchmark CSV); the spec separates CVSS-B from CVSS-BE. Vulture-AI uses the v3-style numeric score, not a v4.0 vector. See CLAIM and LITERATURE_REVIEW §G.
- **Verified directly:** Yes (metric groups, Exploit Maturity, Requirements, Supplemental, and nomenclature confirmed on the page). The full text was truncated in retrieval, so individual formula details were not re-checked.

### R2. CVSS v3.1 Specification Document
- **Title:** Common Vulnerability Scoring System v3.1: Specification Document
- **Authors / body:** FIRST.Org, Inc.
- **Date:** not displayed in the retrieved text. The release year (2019) is the manuscript's own claim and was not confirmed from this page.
- **Venue:** FIRST official specification
- **Link:** https://www.first.org/cvss/v3.1/specification-document
- **Contribution:** Base metrics AV/AC/PR/UI/S/C/I/A; Temporal metrics E/RL/RC; Environmental CR/IR/AR and Modified metrics; qualitative rating scale (Table 14).
- **Limitations:** Temporal and Environmental metrics are optional and "considered Not Defined" if omitted.
- **Relationship to Vulture-AI:** the benchmark's `cvss` column is a v3.x-style base score. The manuscript's `\cite{first2019cvss}` points to the v3.1 spec, which is the correct version for this usage.
- **Verified directly:** Yes.

### R3. FIRST EPSS (program and FAQ)
- **Title:** Exploit Prediction Scoring System (EPSS): FAQ / product page
- **Authors / body:** EPSS Special Interest Group at FIRST; scores generated by Empirical Security
- **Date:** current pages; daily scores
- **Venue:** FIRST official web resource
- **Link:** https://www.first.org/epss/ and https://www.first.org/epss/faq
- **Contribution:** EPSS estimates the probability of exploitation activity observed in the next 30 days (0–1), updated daily, plus percentiles.
- **Limitations (as stated by FIRST):** EPSS is "not a complete risk score"; it "does not account for any context for specific instances"; "Does recent exploitation activity change the score? No"; a score of 1.0 is not claimed for known-exploited items.
- **Relationship to Vulture-AI:** Vulture-AI uses EPSS as `E`. FIRST states EPSS "is part of a risk calculation" and "provides the threat likelihood component only", which supports describing VRS as a composite and not as an EPSS-based risk score.
- **Verified directly:** Yes (FAQ page fetched; quotations above are from that page).

## 2. Prompt-injection and RAG security

### R11. Lewis et al. — Retrieval-Augmented Generation
- **Title:** Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks
- **Authors:** P. Lewis, E. Perez, A. Piktus, F. Petroni, V. Karpukhin, N. Goyal, H. Küttler, M. Lewis, W. Yih, T. Rocktäschel, S. Riedel, D. Kiela
- **Date:** arXiv 2020-05-22 (v4 2021-04-12)
- **Venue:** NeurIPS 2020 (arXiv comments: "Accepted at NeurIPS 2020")
- **Link:** https://arxiv.org/abs/2005.11401
- **Contribution:** RAG combining parametric seq2seq memory with a dense non-parametric index; introduces RAG-Sequence and RAG-Token.
- **Limitations:** evaluated on open-domain QA and generation over Wikipedia; does not address adversarial retrieved content.
- **Relationship to Vulture-AI:** foundational citation for the RAG pattern. Vulture-AI's assistant is RAG in the sense that it retrieves local records; it does not use a dense index.
- **Verified directly:** Yes (arXiv page). Venue confirmed from arXiv comments only; the NeurIPS proceedings page was not fetched.

### R12. Greshake et al. — Indirect Prompt Injection
- **Title:** Not what you've signed up for: Compromising Real-World LLM-Integrated Applications with Indirect Prompt Injection
- **Authors:** K. Greshake, S. Abdelnabi, S. Mishra, C. Endres, T. Holz, M. Fritz
- **Date:** arXiv 2023-02-23 (v2 2023-05-05)
- **Venue (as in bib):** AISec 2023 (ACM Workshop on Artificial Intelligence and Security), pp. 79–90. **The venue and pages are not confirmed** by the arXiv page.
- **Link:** https://arxiv.org/abs/2302.12173
- **Contribution:** introduces indirect prompt injection: adversarial instructions in data an LLM application retrieves; demonstrates attacks against Bing Chat and GPT-4 applications.
- **Limitations:** attack demonstrations, not a defense; the paper states that "effective mitigations ... are currently lacking".
- **Relationship to Vulture-AI:** directly motivates the threat model in the manuscript (instructions in service banners).
- **Verified directly:** Yes for title, authors, arXiv date. **Venue/pages: UNVERIFIED**; the bib entry must be checked against the ACM proceedings before the venue is claimed.

### R13. Liu et al. — Formalizing and Benchmarking Prompt Injection
- **Title:** Formalizing and Benchmarking Prompt Injection Attacks and Defenses
- **Authors:** Y. Liu, Y. Jia, R. Geng, J. Jia, N. Z. Gong
- **Date:** arXiv 2023-10-19 (v5 2025-11-12)
- **Venue:** USENIX Security Symposium 2024 (per arXiv comments)
- **Link:** https://arxiv.org/abs/2310.12815
- **Contribution:** formal framework for prompt-injection attacks and a benchmark of 5 attacks and 10 defenses across 10 LLMs and 7 tasks.
- **Limitations:** benchmark evaluation; defenses are not claimed to be complete.
- **Relationship to Vulture-AI:** offers a benchmarking methodology the Phase 4 evaluation could be aligned with. Not yet cited in the manuscript.
- **Verified directly:** Yes (arXiv page).

### R14. Hines et al. — Spotlighting
- **Title:** Defending Against Indirect Prompt Injection Attacks With Spotlighting
- **Authors:** K. Hines, G. Lopez, M. Hall, F. Zarfati, Y. Zunger, E. Kiciman
- **Date:** arXiv 2024-03-20 (v1)
- **Venue:** arXiv preprint (no venue shown on the arXiv page)
- **Link:** https://arxiv.org/abs/2403.14720
- **Contribution:** spotlighting: transformations (e.g., delimiting, datamarking, encoding) that give the model a continuous signal of which input is untrusted. Reports reduction of attack success from above 50% to below 2% with GPT-family models in the authors' experiments.
- **Limitations:** the authors' own experiments with GPT-family models; results are not independently replicated here; the arXiv abstract does not claim general robustness.
- **Relationship to Vulture-AI:** a provenance-marking defense, closest in spirit to Vulture-AI's source separation. Vulture-AI does not implement spotlighting; it is a candidate for future work.
- **Verified directly:** Yes (arXiv abstract page). I did not read the full paper.

### R15. Chen et al. — StruQ
- **Title:** StruQ: Defending Against Prompt Injection with Structured Queries
- **Authors:** S. Chen, J. Piet, C. Sitawarin, D. Wagner
- **Date:** arXiv 2024-02-09 (v2 2024-09-25)
- **Venue:** "To appear at USENIX Security Symposium 2025" (per arXiv comments)
- **Link:** https://arxiv.org/abs/2402.06363
- **Contribution:** separates prompts and data into two channels; fine-tunes a model to follow instructions only in the prompt channel.
- **Limitations:** requires a specially trained model, so it is not a drop-in filter for an existing LLM API. The paper claims "little or no impact on utility".
- **Relationship to Vulture-AI:** Vulture-AI cannot use StruQ because it relies on a commercial or local LLM it does not train. StruQ is an architectural alternative, not a comparison baseline.
- **Verified directly:** Yes (arXiv page). Venue taken from arXiv comments only.

### R16. Chen et al. — SecAlign
- **Title:** SecAlign: Defending Against Prompt Injection with Preference Optimization
- **Authors:** S. Chen, A. Zharmagambetov, S. Mahloujifar, K. Chaudhuri, D. Wagner, C. Guo
- **Date:** arXiv 2024-10-07 (v3 2025-07-03)
- **Venue:** "ACM CCS 2025" (per arXiv comments); related DOI 10.1145/3719027.3744836 listed on arXiv
- **Link:** https://arxiv.org/abs/2410.05451
- **Contribution:** preference optimization on prompt-injected inputs to prefer secure over insecure outputs. The authors report attack success rates below 10% on tested attacks.
- **Limitations:** the authors' own evaluation; the claim applies to attacks similar to those studied; requires model fine-tuning.
- **Relationship to Vulture-AI:** a training-time defense; Vulture-AI is inference-time and deterministic. Not directly comparable.
- **Verified directly:** Yes (arXiv page). The related DOI was shown on the arXiv page; I did not open it.
